## 建議實作順序

1. 先做 P0 的兩項，最快看到 webhook 體感改善。
2. 再做 P1 的寫入優化與 request-scope cache，這會進一步壓低長尾延遲。
3. P2 屬於菜單與回執體驗優化，適合在主流程穩定後處理。
4. P3 是中期架構題，只有當訂單量、查詢量、併發量都持續成長時才值得啟動。

## 驗收指標建議

1. 下單請求從收到 webhook 到回 ACK 的時間。
2. 下單請求從收到 webhook 到整個 doPost 結束的總時間。
3. 「我的訂單」、「今日統計」、「本週統計」第二次查詢的時間是否明顯低於第一次。
4. 寫入後查詢是否立即反映最新結果，避免快取造成資料延遲。
5. 尖峰時段或多人連續下單時，失敗率與超時率是否下降。
